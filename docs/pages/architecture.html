Three builds, one image

A reference for how masqueradarr is built: the three-build layout, the container topology, the declared-capability contract, the internal seams and DNS, the load-bearing boot order, the REST + WebSocket surface, the Docker images, and what's still on the roadmap.

01 Three builds, not a monorepo

Built and versioned independently

masqueradarr is two npm packages plus one Rust crate — not a workspace, and the two packages never import across the boundary. The Docker image stitches all three together.

● / (root) · SPA

Vue 3 + Vite

The management front end (hls.js, vue-router, mitt; Video.js for the pop-out Ultimate Video Player; react / react-dom only for the live-chart bridge). TypeScript strict: false. npm run build (vue-tsc -b && vite build) is its type-check.

● server/ · API

Express 4 + Mongoose 8

ESM, TypeScript strict: true, explicit .js extensions on every relative import. Its npm run build is an esbuild bundle + minify that does no type-checking — npm run typecheck is the gate.

● proxy/ · masq-proxy

Rust data plane

axum / tokio / reqwest. CI builds it, lints it with cargo clippy -- -D warnings, and runs its in-file cargo test suites.

development

Two dev servers side by side: the SPA on :5173 (Vite, proxies /api and its WebSockets → :3000) and the API on :3000 (tsx watch, needs a reachable MongoDB). There is no test runner and no linter — the type-check is the test. The root CI builds the SPA and the Rust crate; the backend's gate runs in its own repository's CI.

  • Node — the brains. Per-source auth, scraping, vetting upstream-supplied URLs, per-source stream limits, the stream-token gate, telemetry authority and config storage.
  • Rust — the muscle. Fetch upstream, follow redirects, rewrite .m3u8, enforce the SSRF gate and pipe segments. It is driven per stream by a grant from Node and never branches on which provider it is serving — what a source needs arrives as declared grant fields. Every redirect hop passes the same SSRF check as the first request.
  • Sources adapter framework — a source-agnostic core (sync → normalize → dedupe → resolve) with ~17 built-in adapters, the proxy-only direct / hdhomerun / local sources, and a rebel adapter registered only while the Rebel IPTV companion is enabled. See Sources.
  • Channel model — a pristine sourcechannels reference projected into an editable playlistchannels; edits survive re-syncs. Channels can be grouped into failover groups — one parent, ordered backups. See Playlists.
  • EPG + scheduler — multiple ingesters behind one sync path, driven by a croner scheduler over cronjobs. See EPG.
  • Video proxy engine — the remux-free Rust data plane. See Video proxy engine.
  • Local origin — an opt-in inversion of the data plane: one shared ingest per channel fills a RAM ring and masqueradarr publishes a playlist it authored itself. Forced on for any source that declares originRequired. See Local origin.
03 Declared capabilities

No source === '…', anywhere

When a source needs different behaviour from the core, it declares a capability rather than being special-cased by id. Neither the Node core nor the Rust engine ever tests which source it is handling.

CapabilityDeclared onWhat the core does with it
playerSelectableadapterAn alternate-upstream stage before failover children; the player picker in the UI.
probeExemptadapterThe scheduled probe sweep skips the source's channels (per channel, on origin ?? source).
maxConcurrentStreams()adapterThe resolve seam counts each live stream against the adapter serving it (failover backups included) and refuses a new one over the cap — a definitive 429 source_stream_cap, or a walkable 502 when a failover backup elsewhere could carry it.
applyEpgLinks()adapterRe-run after every successful Gracenote / Jesmann guide sync — and after such a guide is added — for built-ins that crosswalk onto guides they don't own.
adSignatureproxy bagRides the grant; the local origin's ad classifier for sources with no cue tags.
originRequiredproxy bagForced into the grant's proxyConfig.originEnabled, whatever the proxy config says.
segmentUnwrapproxy bagRides the grant; the pass-through byte paths strip a disguised segment's container prefix.

The /api/sources manifest publishes the flags the SPA needs (playerSelectable, probeExempt, originRequired), so the UI never hardcodes a source list either.

04 The internal seams & DNS

One loopback channel, one set of nameservers

Rust calls Node over POST /api/internal/* on loopback, guarded by a shared x-masq-secret: resolve (the per-stream grant), telemetry and log (batched), and — in edge mode only — authorize. Rust never reads MongoDB. The full grant shape is on the Video proxy engine page.

● live config, no restart

Echoed on every flush

The telemetry and log responses echo { logLevel, nameservers }, and both are stamped into the sidecar's environment at spawn (MASQ_LOG_LEVEL, MASQ_NAMESERVERS). Changing verbosity or DNS on the Settings screen reaches the data plane within one flush.

● data-plane dns

Same rules as Node's resolver

The Settings nameservers drive Rust's upstream lookups: configured servers first, the OS resolver on any failure (NXDOMAIN included, so .local / LAN names keep working), IP literals never resolved, A before AAAA. Single-label names such as Docker service names go straight to the OS resolver, and Rust's own loopback calls to Node always stay on the system resolver — no DNS setting can cut the data plane off from its control plane.

06 REST + 4 WebSockets

The request surface

Every routes/*.ts is a thin router over one model. Handlers are async (req,res,next) wrapped in try/catch(next); reads use .lean() + { _id: 0 }; error bodies are { error: '<snake_case>' }. Live data is pushed over WebSockets, not polled.

WebSocketCarries
/api/dulo/login-streamThe server-streamed Chromium dulo login capture
/api/stream-statsViewer / bandwidth / buffering telemetry (Active Streams + History / Metrics)
/api/logs-streamThe live "View logs" drawer feed
/api/system-statsLive CPU / memory push (Dashboard)
websockets carry the session token

A browser can't set an Authorization header on a WebSocket, so the SPA appends its session token as ?token=. The upgrade handler refuses a cross-origin request, an unknown path, or anything but an admin session (a stream token is not enough) with a 401 before any of the four sockets is attached.

07 The Docker images

One release, two products — plus a no-AVX variant

Both are multi-stage builds (SPA → server → Rust proxy → runtime) on Debian bookworm (glibc) with Node 22 under tini. They share the base and the apt Chromium; the one intentional divergence is the config bootstrap / supervisor.

● app.Dockerfile

The standard image

App only, for the compose stack — pairs with an external mongo service. The container self-provisions its config.json from .env on boot (docker/app-entrypoint.sh). No host config mount. The compose file also carries the optional rebel-iptv and docker-sock-proxy services at scale: 0.

● aio.Dockerfile

The all-in-one image

App + mongod 7.0 + config bootstrap in one container. A root supervisor (aio-entrypoint.sh) writes config, starts mongod (--auth, loopback-only), waits for it, then starts node. One /data volume persists everything. With DOCKER_SOCK_ACCESS=1 it can also manage a Rebel IPTV sibling container.

no-avx hosts · mongo4.4- tags

On amd64, MongoDB 7.0 needs a CPU with AVX; without it mongod dies at boot with Illegal instruction (Synology NAS, Atom / Celeron, older Xeons, kvm64 / qemu64 VMs). The AIO image is also built with MongoDB 4.4 under the mongo4.4- tags (e.g. mongo4.4-latest). It needs a fresh /data volume — 4.4 can't open a 7.0 database — so move data with a backup from Settings → Data and a restore.

Multi-arch build & push (amd64 + arm64) publishes the images in one release. The runtime layout (/app/dist, /app/public, /app/compose, /app/config, /app/seed-data) is load-bearing and stays in sync with server/src/paths.ts.

08 MASQ_EDGE topology

An opt-in inversion of the public socket

By default Node owns the public port and Rust is a loopback sidecar. MASQ_EDGE=1 inverts it — Rust binds the public port, serves streams in-process (token-gated via POST /api/internal/authorize, 30-second revocation TTL), and reverse-proxies the SPA, /api/*, downloads and all four WebSockets back to Node on a loopback port. Same public port and DOMAIN; reversible by clearing the flag. The Rebel dashboard gate keeps its own port either way. The topology diagrams and the "when to turn it on" guidance are on the Video proxy engine page.

09 Roadmap

What's live, and what's next

The rename and re-architecture are effectively complete — codebase, brand, runtime and images are all masqueradarr, and playback is live over the Rust engine (HLS + raw-TS). The data plane has since grown an opt-in local origin that decrypts AES-128, unwraps disguised segments and segments bare MPEG-TS in-engine, which retired most of what used to sit behind “needs a remux”. What genuinely remains:

● live today

Working now

  • Resolve-on-demand catalog + ~17 adapters, and the optional Rebel IPTV companion
  • Rust HLS + raw-TS proxy (retry, re-resolve, signed-URL renewal, buffer)
  • Failover groups — ordered channel backups, cross-provider
  • Per-source stream limits; data-plane DNS + SSRF gate
  • Users, roles, tokenized M3U / XMLTV export
  • Live telemetry, logs, scheduler, backup / restore
● on the roadmap

Designed / pending

  • Remux / transcode — still no ffmpeg. (HDHomeRun TS→HLS no longer needs one: see local origin.)
  • Seamless mid-stream failover splice (today: establish-time)
  • HDHomeRun-tuner & Xtream-panel emulation
  • ?fmt=ts per-request override; segmentCacheTtlSec (shipped in the grant, not yet enforced)
  • A full runtime end-to-end pass of edge mode on a live stack
